# v0.22 Compatibility

Millrace v0.22 deliberately does not preserve the v0.21 runtime shape.
`Removed` means the old surface is not a v0.22 API. `Deferred` means the
surface is outside v0.22; no delivery date is implied.

| Surface | Disposition | v0.22 replacement or boundary |
| --- | --- | --- |
| v0.21 workspaces, configs, snapshots, imports, and schema upgrades | Removed | Initialize fresh v0.22 state. There is no legacy reader, schema migration, automatic conversion, or state repair path. |
| Root CLI aliases | Removed | `add-task`, `add-spec`, `add-probe`, `add-idea`, `pause`, `resume`, `stop`, `retry-active`, `clear-stale-state`, and `reload-config` are absent. Use current queue, wait, intervention, status, and daemon commands. |
| Mailbox and control routing | Removed | Use direct local operator commands plus daemon lock and signal behavior. |
| Runtime lock and stale-state compatibility commands | Removed | Use current daemon locking, waits, interventions, and process signals. |
| Old config show/validate/reload, mode, and model aliases | Removed | Use explicit workflow selection and local runner adapter configuration. |
| Legacy entrypoint helper Python modules | Removed | Use current workflow package manifests, selected assets, and validation. |
| Runtime skill lifecycle and remote skill index | Removed | Plus-owned authoring skills are packaged advisory assets, not runtime-installed workflow authority. |
| Workspace map, history log, and baseline seeded files | Removed | Use durable state, status, trace, and selected package assets. |
| Old bundled workflows, package layouts, baseline assets, and compatibility profiles | Removed | Import current `millrace-plus` manifests and assets. Authored compatibility profiles are refused. |
| Broad legacy doctor parity | Removed | v0.22 provides package doctor and a minimal read-only workspace/runtime doctor. |
| File watcher and ideas inbox intake | Deferred | Intake is through explicit queue, package, and operator commands. |
| Provider callbacks, webhooks, and generic source adapters | Deferred | No callback, webhook, or source-adapter intake runs in the base runtime. |
| Blueprint Planning assets | Deferred | No v0.22 official workflow selects `planning.blueprint`. |
| Rich monitor logs and dashboard views | Deferred | Bounded local `--monitor basic` is supported. |
| Rich run tail and status watch | Deferred | Run list/show, status, trace, and finite bounded `runs follow` projection are supported. |
| Pi RPC | Deferred | Pi RPC is not a v0.22 runner. |
| Claude Code, OpenCode, OpenHands, and other runner kinds | Deferred | v0.22 supports Millforge and Codex. |
| Broad capability catalogs and policy gates | Deferred | v0.22 enforces selected runner dispatch gates. |
| Capability grant audit and revocation | Deferred | Broader grant lifecycle is outside v0.22. |
| General manual-approval framework | Deferred | Selected operator waits and interventions are supported. |
| Daemon ceilings | Supported | Schema-8 daemon budget epochs enforce optional wall-time, accepted-start, and reviewed adapter-reported total-token ceilings. Token counters are execution evidence, not billing truth. |
| Provider billing, spend, pricing, quotas, and rate policy | Deferred | Provider invoices, spend, prices, and rate-limit truth remain outside v0.22. |
| Real provider effects | Deferred | Selected effect declarations may exist as workflow data; provider code, credentials, execution, and external reconciliation are not supported. |
| Legacy `millrace-web` sidecar | Deferred | It is not distributed with v0.22. Millrace OS is separate future UI/control-plane scope. |
| Marketplace and executable plugins/connectors | Deferred | Workflow packages are imported explicitly; package data cannot grant executable authority. |

## Supported v0.22 Boundary

v0.22 supports:

- compiler-validated workflow packages and immutable selected plans;
- durable local queues, runs, artifacts, waits, interventions, and traces;
- schema-8 durable daemon ceilings over wall time, accepted starts, and
  reviewed adapter-reported token evidence;
- explicit local operator commands;
- daemon execution through selected Millforge or Codex runner authority;
- bounded `--monitor basic` output;
- workflow package path, archive, and installed-distribution import/export;
- selected entrypoint and stage-core materialization from validated package
  bytes;
- selected fanout, join, recovery, quarantine, operator-wait, and completion
  behavior represented in compiled workflow data.

An absent legacy command normally produces the current parser or
`command_not_implemented` error. Authored compatibility profiles produce
`unsupported_compatibility_profile`. Unsupported selected adapter authority
can produce `adapter_kind_refused`. These are current refusal categories, not
migration facilities.

## Schema 6 And 7 To Schema 8

Dispatch-suspension persistence requires store schema 8. The runtime does not
initialize new tables over an existing schema-version-6 or schema-version-7
database and performs no automatic migration. Any command that recognizes an
otherwise valid exact schema-6 or schema-7 workspace returns
`workspace_upgrade_required` with exit status 4. The database, CAS, and
runner-event sidecar remain byte-for-byte unchanged.

Missing or malformed metadata, versions below 6, and future or unknown schema
versions keep their existing unsupported/corrupt-state behavior; they are not
misreported as the exact upgrade boundary. A later one-shot migration would
require a separate reviewed contract.

Operators must finish or retire active v0.22 work with the v0.22 runtime.
Then initialize a new schema-8 workspace and re-admit current packages
and plans. No runner session is inferred for an active pre-session run.
