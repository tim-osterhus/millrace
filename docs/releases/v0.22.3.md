# Millrace v0.22.3 release candidate

Sibling failures that arrive during a pending recovery cooldown retain their
durable completion until the actual due timer runs. They then apply exactly
once under the existing counter policy; superseded timer-created recovery
activations are not treated as runnable work or unexplained corruption.

Millrace v0.22.3 is the planned governed-context/runtime-integrity
release for the general `millrace-ai` runtime. This document describes the
candidate; it is not evidence of publication. Workflow-specific context meaning
remains in workflow packages, while the runtime owns only compiled authority,
durable evidence, and safe delivery.

## MVP scope

The experimental LAD semantic-workspace workflow is deferred from the scoped
MVP and excluded from the corresponding Plus distribution. Generic context
bindings, authenticated checkouts, selective hydration and integrity checks
remain available to explicitly selected workflows. Ordinary LAD and Planning
remain workflow-package behavior, not runtime defaults.

The evaluation did not establish a semantic-workspace efficacy benefit or
fundamental incompatibility. Its final task required an unavailable released
lower-layer contract. This cut preserves the experiment separately and retains
independently justified generic runtime fixes; it does not claim a successful
Control/Treatment comparison.

## Install

Publication is on hold. For current candidate qualification, install explicit
member wheels as described in [Getting Started](../getting-started.md).
The published `millrace` bundle remains v0.22.2; there is no v0.22.3 bundle.

Only after the qualified Core artifact is published:

```bash
python -m pip install "millrace-ai==0.22.3"
millrace --version
```

The v0.22.3 tag workflow publishes the `millrace-ai` wheel and source
archive only. The removed `millrace-web` sidecar is not part of this
distribution.

## Governed Context

- Context binding schema 2 is distinct from the current schema-3
  `millrace.context_checkout_manifest`, which authenticates captured roots and
  files.
- Compiled schema-18 bindings carry required and discoverable sources, bounded
  hydration limits, mutation policy, and retention policy with no hidden
  runtime defaults.
- Discoverable content is catalog-only at runner start. The exact
  `millrace context select` command hydrates selected paths read-only and
  records idempotent receipts against the manifest and CAS.
- Optional source `max_files`/`max_bytes` caps bind actual enumeration and
  payload reads. Omitted declared roots retain authenticated missing, empty,
  file, and directory baselines, so protected create/delete/rename/type/over-
  limit mutations refuse.
- Concurrent selections for one runner session are serialized across
  verification, cumulative-limit enforcement, materialization, receipt
  persistence, and final read-only-mode validation.
- `millrace context diff` provides an authenticated, read-only projection of
  exact direct-write file changes for a live write-enabled session. Workflow
  packages decide whether to consume it; the command does not persist evidence
  or assign workflow-specific classifications.
- Selected-root mutation is reconciled before runner evidence is applied.
- Deterministic writeback refusals retain their exact bounded public reason;
  exception-local scan and validation details are reduced to stable redacted
  categories.
- Honest attribution records source and availability for observed metrics;
  unavailable values are not reported as zero.
- After durable terminal completion, cleanup removes only derived session
  material. CAS objects, manifests, receipts, results, usage, attribution, and
  events remain durable.

## Runtime-owned counter thresholds

Compiler and admission both check runtime-owned counter threshold/increment
actions for the same normalized artifact schema and normalized condition
compatibility. Threshold conditions may only be an exact key/value subset of
increment conditions. Component-bound dispatch exposes only terminal outcomes
selected by the component's compiled terminal-result mappings. For non-recovery
counter thresholds intentionally omitted from those mappings, the runtime alone
promotes the neutral increment action when the durable counter reaches its
threshold. Codex terminal contracts also carry compiled artifact-field
conditions so provider wrappers can constrain marker/artifact pairings.
Recovery-attempt context projections recognize the same compiled counter
threshold authority as admission and runtime routing: a recovery threshold is
valid only when its counter increment belongs to the selected recovery policy.
When that authority creates a cooldown wait, an activation-free daemon tick
now observes and applies a due timer before selecting runner work. The wait
duration and recovery destination remain compiled-plan authority; the base
runtime supplies only the generic deterministic scheduler.

## Compatibility

Published v0.22.2 workspaces use store schema 8. This candidate requires fresh
schema-10 state; no in-place migration from schema 8 or 9 is provided. Preserve
old state and finish or retire its work with the matching runtime before using
a separate fresh candidate workspace.

This cut does not add run-scoped pause/resume. Selected-plan dispatch
suspension is not a substitute for that capability. Workflow prerequisites
must be checked against the actual released contract before enqueueing work.

Closure payload limits remain selected package authority. The current public
Plus Planning declaration has a 16,384-byte closure request ceiling; the
campaign-only increase is not part of this release. Millforge separately
limits its assembled instruction envelope to 65,536 bytes. A larger selected
payload limit does not override that adapter ceiling, and requests may refuse
before provider execution. No runner-capacity redesign is included here.

Unreleased schema-17 plans are historical evidence, not compatible plans.
The runtime refuses context-bound plans using that shape. Import and select a
schema-18 plan before running it under v0.22.3. Unbound schema-18
plans remain valid when their selected authority is otherwise admissible.
