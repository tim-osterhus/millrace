# Runner runtime-failure recovery invariant matrix

This matrix supplements the recovery cooldown matrix. Mechanical failures use
selected recovery authority without synthesizing runner output. The existing
recovery policy retains its attempt limits, cooldown and quarantine behavior.

| Boundary | Source authority | Normalization/admission | Legal runtime sequence | Illegal/refused sequence | Durable invariant | Exact proof |
| --- | --- | --- | --- | --- | --- | --- |
| Failure mapping | Binding stage/failure/action tuple | Only timeout, own stage, existing recovery action and exactly one policy; no artifact requirement | Schema 5/6 selected binding maps a clean timeout | Missing, duplicate, foreign, non-recovery or artifact-bearing map | Unmapped schema 3/4 bytes and fingerprint remain unchanged | `tests/compiler/test_runtime_failure_mappings.py` |
| Failed completion | Run/session/dispatch/claim/fences plus canonical diagnostic CAS | Exact bounded timeout envelope | Failed/error completion, cleanup complete, no cancellation or result evidence | Wrong echo, missing diagnostic, cancellation, incomplete cleanup, non-timeout | Failed completion remains unchanged; no runner result or observation created | `tests/cli/test_cli_runtime_failure_recovery.py`; `tests/substrate/test_runtime_failure_integrity.py` |
| Recovery application | Selected route and source claim | Typed `ApplyRunnerRuntimeFailure` full payload digest | Apply once and create real recovery activation | Forged receipt, audit, route, source or target | Receipt, transition, audits and recovery effects must agree on reload | `tests/kernel/test_runtime_failure_adversarial_review.py`; `tests/substrate/test_runtime_failure_integrity.py` |
| Source settlement | Exact accepted failure application | Authenticated settled predicate | Recovery releases source slot and recovery worker can claim | Concurrent stale session or explicit retry of consumed source | No second observation/application and no active source slot | `tests/kernel/test_runtime_failure_adversarial_review.py`; `tests/kernel/test_runtime_failure_lifecycle.py` |
| Public status settlement | Shared kernel settled predicate plus selected work/activation coherence | N/A: projection adds no authored authority or admission rule | Applied timeout → recovery → returned source ready → normal claim/close → reload | Pending/unmapped/cancelled/unknown failure, forged or missing accepted application, incoherent claim/plan/generation | Status excludes only settled source runs, preserves coherent readiness and does not mutate persisted state | `tests/operator/test_status_runtime_failure_recovery.py::test_status_settles_applied_timeout_through_return_close_and_reload`; `test_status_keeps_unsettled_active_and_failure_states_visible`; `test_status_does_not_settle_a_coherent_run_from_corrupt_failure_provenance`; `test_status_retains_live_run_coherence_guards` |
| Recovery return and reset | Selected recovery policy/return action | Existing recorded-source authority | Timeout → recovery → return → normal source success/close | Fake success or fabricated agent evidence | Later legal history preserves earlier application proof | `tests/kernel/test_runtime_failure_lifecycle.py` |
| Nested recorded-source return | Selected policy, emitting recovery origin and accepted historical source snapshot | Existing source/return declarations; no new schema, route or stage-name exception | Source timeout → recovery timeout or accepted failure outcome → cooldown/TimerDue → recovered return → claim → later return/close or bounded timeout | Forged or stale plan, queue, node, stage, runner, lineage, generation, source/latest links, return effect or receipt/audit | Fresh returned recovery activation/run tracked; exact return effect and historical provenance survive reload and source updates; ordinary source tracking preserved | `tests/kernel/test_recovery_recorded_source_return.py` |
| Returned recovery dispatch | Existing authenticated inherited-input route/timer and recorded-source proof plus one current selected attempt owning the work item/run/activation | N/A: reuse selected recovery provenance; no new schema, stage-name branch or outcome filtering | Claim a recovery activation at its exact recorded graph node and render the selected dispatch, including after reload | Missing, stale, foreign or ambiguous current ownership and missing/foreign route, claim, source, receipt or audit cannot expand ordinary target authority | Earlier accepted origins remain authentic after later recovery updates; only current ownership authorizes a fresh dispatch | `tests/kernel/test_recovery_terminal_context.py` |
| Shared quarantine action | Selected action plus current plan, lineage, recovery run and policy attempt | Existing recovery-policy declarations; shared actions already compile | Current recovery emits its selected quarantine report under the policy owning this invocation | Missing/ambiguous current attempt or wrong latest run/activation retains refusal | Quarantine stores the current policy/attempt and exact emitting invocation | `tests/kernel/test_recovery_terminal_context.py` |
| Diagnostic execution re-entry | Plus-selected COMPLETE payload projection and actual work payload/trusted digest | Existing source/object/coalesce expressions, no new compiler contract | Task timeout → recovery failure outcome → cooldown/TimerDue → COMPLETE report → source-derived QA carrier → Builder claim/render/reload/reset | Old C19 selected projection still rejects absent QA carrier; missing trusted input and invalid report/selector remain refused; existing carrier preserved exactly | Current package changes affect future selection; persisted active plans and rejected candidates retain original authority | Plus `tests/test_recovery_terminal_contract.py` |
| Bounded recovery | Existing policy limits and wait declarations | No new retry count or wait duration | Immediate attempt → cooldown/timer → bounded quarantine | Bypass pending wait, exceed policy, duplicate timer | Original completion remains pending until legitimate application | `tests/kernel/test_runtime_failure_lifecycle.py` |
| Inherited recovery input | Exact selected action/policy plus creating route or consumed timer | Preserve ordinary stage input families | Source task → recovery on inherited task → recurrent timeout → cooldown/timer → quarantine | Missing/duplicate/foreign origin, stale claim, forged wait count or target | Earlier failure proof remains valid after later attempt updates and reload | `tests/kernel/test_runtime_failure_recurrence_review.py`; Plus `tests/test_pi_runtime_failure_recovery.py` |
| Mechanical policy budget | Typed failure command and selected recovery policy | No agent result is synthesized | Mechanical failures reach policy quarantine despite lower agent-action counter threshold | Agent counter changes, ordinary outcome counter bypass, recovery-policy bypass | Agent counter values stay unchanged for mechanical timeout applications | `tests/kernel/test_runtime_failure_recurrence_review.py`; Plus `tests/test_pi_runtime_failure_recovery.py` |
| Restart and drain | Persisted completion and daemon budget | Reconcile before dispatch | Pending timeout applies once; exact replay is a no-op | Drain/cancellation causes new route or mutation | No clock reset, hidden retry or fabricated success | `tests/cli/test_cli_runtime_failure_recovery.py` |
