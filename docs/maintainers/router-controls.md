# Router controls

Millrace 0.23 exposes the same durable operations through `millrace router`,
`python -m millrace.router.cli`, and `millrace.router.control`. A mutator that
acquires the controller lock can remain in the foreground while it runs recovered
work to pause or completion. There is no required daemon.

## Formats and execution dependencies

Authored graphs use `millrace-router/v3`, instances
`millrace-router-instance/v2`, stores `millrace-router-store/v7`, requests
`millrace-router-request/v2`, execution `millrace-router-execution/v2`, and launch settings
`millrace-router-launch-settings/v3`. Old stores refuse before mutation. Use fresh
homes and retain matching old artifacts/state separately.

A binding declares exactly `adapter`, `contract`, `executable`, and `config`.
Invocation fields are binding, timeout_seconds, cwd, inputs, and config. List all
execution controls explicitly in control_files, including command scripts.
Core captures the coherent control-byte closure and executable paths. It never
interprets external profile, prompt, provider or model fields.

Core resolves the builtin command/millrace-command/v1 pair itself. It never
passes that pair to an injected resolver. External hosts explicitly pass an
adapter_resolver keyword to public operations and CLI main; no global registry
or automatic import path exists. Plus supplies its own host over those controls.

Resolver propagation covers load/list/inspect, create/config/validate, all
continuation and stop operations, exact replay, recovery/reconciliation and
release_project_hold, including its owner-store read. A Core-only host refuses an
instance whose captured contracts or unused settings namespaces need an absent
adapter, before appending a request. Use the matching external host or signal the
existing controller. HTTP/UI clients must use the same controls.

## Instance host locators

Creation accepts `--host-paths` as a JSON object of nonempty string aliases to
nonempty string locators. It passes the map to the existing instance controls;
Core interprets no adapter-specific locator policy. Invalid JSON or map values
refuse before an instance is created. Omission selects an empty map.

```sh
millrace router instance create --state-home ./router-state --workflow ./workflow/workflow.json --project ./project --host-paths '{"runtime":"/absolute/path/to/python"}'
```

A graph binding may name `runtime` as its executable. An external adapter can
validate and use other supplied aliases through its public configuration and
invocation records. The matching external host exposes this same create option.

## Settings and validation

Common fields are runtime_defaults binding/timeout_seconds and operator_policy
binding_pin/timeout_ceiling_seconds. Workflow, plane and node overrides inherit
in that order under policy. Invalid explicit values refuse even if shadowed.
Missing timeout selects 1800 seconds with timeout_defaulted; explicit inheritance
is quiet. Warnings identify the exact plane and local node.

Runtime/workflow/plane adapter_settings is an object keyed by opaque adapter ID with
exact contract/config members. The matching adapter validates all explicit
namespaces, including unused ones, on create/config/validate/start/reload.
Context-free capture does not interpret adapter configuration. Selected-context
validation calls pure configuration validation and pure per-node planning.

Validation returns resolved_nodes[plane_id][node_id] as format/common/adapter. Common includes
runtime_settings_version, requested/effective, provenance and warnings. Adapter
settings have their own requested/effective/provenance/warnings. Validation uses a
never-materialized sentinel invocation identity/root. Real reservation compares
settings from the real plan with those validated settings before counting work.

Generic plan checks reject colliding environment additions, unsafe or overlapping
generated destinations, invalid JSON and oversized handoff fields. Destination
comparisons use Unicode NFC normalization and case folding to keep generated
paths distinct and outside captured controls; authored spelling and bytes remain
unchanged. Canonical
argv/environment/details/settings/generated-metadata JSON is limited to 1 MiB
per field; generated raw controls total at most 1 MiB + 64 KiB. Generated bytes are
re-derived from captured authority; only their sizes/hashes persist. Live external
prerequisites belong inside the adapter invocation, before any external process.

## Durable completion and writer holds

Reservation freezes the producing revision, actual plan, effective settings,
locators and deadlines before any probe or main process. A plan refusal pauses
invalid_launch_plan without creating/counting an invocation. Correct the pending
configuration through normal edit controls before continuing; exhausted run bounds
still take precedence.

Core validates returned envelope/evidence before raw commit. Completed transport
requires integer exit code zero. Raw stdout/stderr and UTF-8 diagnostics are bounded
at 64 KiB each. Malformed external returns retain the counted invocation as
uncertain, pause writer_unknown and preserve the project hold. They never poison
subsequent inspection or manufacture stopped closure.

Raw completion commits before semantic json-v1 parsing and result-ref admission.
Duplicate completion compares origin, diagnostics, bytes, execution/writer/exit
facts and evidence; changing any fact refuses conflicting_completion. Core alone
assigns preparation/interruption origins under mechanical predicates. External
results cannot request an origin exemption.

A valid final result and certain writer closure are separate facts. Uncertain
writers block routing/replacement. Reconciliation records stopped-writer authority
without rewriting an existing completion. If none exists, its atomic transaction
creates a Core interruption plus its matching writer fact. Explicit resume follows;
failed or interrupted work cannot become a successful result.

## Requests, edits and shutdown

Retain CLI request_envelope output. Replay requires an explicit state home and
returns the exact retained receipt. Reusing a request ID for changed content refuses.
Expected state versions apply at application time; stop controls retain their
existing guarded behavior. Creation IDs derive from the selected home/request ID.

One holder owns each instance's lock, queue drain and engine. Diagnostic validation
and reads do not advance work. A draining holder admits stops/diagnostics and
refuses other mutations; later continuation follows its exit and lock release.
Pause allows active work to finish. First SIGINT/SIGTERM requests pause; a repeated
stop requests cancellation. Closing-path repeated signal admission remains required.

Locked is the startup default. Completed results persist before handling edits.
Live mode validates/activates a coherent pending revision, parses using the
producing launch contract, and routes under the activated revision. Locked changes
pause before further routing. Invalid/incompatible edits preserve the result and
consumed bounds. Active external adapter/configuration changes affect later launches.


## Plane controls and stop facts

Graphs explicitly declare each plane's workspace, start and local nodes. Identical
node names in different planes are independent. Graph goto/retry/pause/finish
stay within the selected plane; graph finish does not terminate runnable siblings.
The run's invocation cap and deadline are shared and never reset by retries,
recovery or edits. The last allowed completion routes before deciding whether a
new reservation would exceed the cap.

Use `pause-plane`, `resume-plane`, `cancel-plane` and `redirect-plane` with
`--plane PLANE_ID`; `retry` and `reconcile` also require `--plane`. The old
`redirect` form is unsupported. Run `pause`, `resume` and `cancel` are aggregate
controls. A graph/operator-paused plane may coexist with active siblings.
A derived `no_runnable_planes` pause creates no run gate: resume the desired plane.
An explicit run pause requires run resume/accept before any plane can dispatch.
Targeted continuation may mark a plane ready behind that gate, but cannot clear it.
Run resume clears only the explicit gate and preserves individual plane pauses.

Request/v2 contains exactly format, operation, instance_id, run_id, plane_id,
request_id, expected_state_version and payload. Stops have null expected version;
ordinary mutations use the current run version (start/config use the instance
version). Start has null run/plane IDs and returns its generated run identity.
Aggregate controls have null plane ID; targeted controls require the exact ID.
Applied stops expose sorted `target_planes` and `active_invocations`, including
reserved invocations still preparing/probing before a process acknowledgement.
Queued receipts claim no applied snapshot. Exact replay returns the original
receipt, even after those invocations have completed; it never signals again.

Inspection exposes an explicit `planes` map, aggregate count/invocations,
`inflight_invocations` and effective-writer `quiescent`. A process callback only
returns after the owner commits its started fact. Worker polls observe cancellation
flags; only the controller drains controls or commits SQLite state. The holder
joins every owned worker and completes its final ordered control drain before
return. Completed unknown/may_live external writers remain separate authoritative
facts and retain the project hold until supported reconciliation. A transport or
client response alone cannot prove that a writer stopped.

A consumer's graph retry or explicit self-resume pause pins the same selected
seam input. Goto (including goto-self), finish and other pauses acknowledge once
when routing commits. Gates never acknowledge. Redirect while pinned refuses;
manual retry accepts only the current pinned consumer invocation lineage, and
retry of acknowledged input refuses. Ordinary eligible prior-invocation retry
remains available within its unpinned plane. Pending occurrences retain FIFO order
across restart and producer termination; exhausted input or impossible terminal
dependency pauses only the affected plane.
